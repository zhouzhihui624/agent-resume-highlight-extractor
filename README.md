# AI Agent 简历亮点提取器

一个面向 AI 应用开发、AI Agent 和大模型工程项目的 Codex Skill。它会先核对项目中的真实机制，再从中选择适合实习生承担的有限职责，直接整理成能够写进简历、也经得住面试追问的项目亮点。

## 能做什么

- 从代码、设计文档、测试、评测、运行轨迹和提交记录中发现候选亮点
- 把项目能力收敛成实习生可信的模块、链路、实验、接入或验证职责
- 合并重复主题，优先保留 2-5 个证据充分、技术深度较高的亮点
- 从功能背后还原工程问题、简单方案的不足和可验证结果
- 默认直接使用“参与建设”“负责其中某环节”等有限职责表述，不因缺少个人提交证明停下来
- 把每个亮点组织成一条因果主线，并使用三个稳定设计锚点帮助理解和复述
- 最终只保留一份主题文档时，用“主线正文 + 技术深挖附录”同时保证可记忆性和技术完整性
- 从同一主线生成简历 Bullet、连续面试讲法、STAR 和高频追问
- 主动提炼机制对应的定性价值、上线用途和可量化指标方向
- 对 AI Harness、Agent Runtime、模型评测、工具调用、状态恢复和人工审批等主题进行证据分级
- 默认使用一张中文总流程图，并在三个对应步骤中就地讲清实现、失败、验证和取舍
- 使用循序渐进的中文解释专业术语，避免把关键实现藏到高频追问中
- 区分正式亮点、总览、关系说明、独立项目和候选材料，避免所有文件硬套同一模板

## 目录结构

```text
.
├── SKILL.md                              # Skill 的核心规则与执行流程
├── agents/openai.yaml                    # 展示信息和默认提示词
├── evals/evals.json                      # 行为评测用例
├── evals/trigger-queries.json            # 触发与不触发样例
├── scripts/validate_saved_package.sh      # 深挖文档包结构校验
└── references/
    ├── evidence-and-theme-guide.md        # 证据审查与亮点筛选指南
    └── output-recipes.md                  # 简历、STAR 和文档包输出模板
```

校验正式亮点时可以显式指定文件模式，避免把总览、关系说明和候选材料套入同一模板：

```bash
./scripts/validate_saved_package.sh <文档目录> \
  --deep-zh --no-code --theme-glob '0[1-4]-*.md'
```

`--deep-zh` 检查问题、流程、实现、失败、验证、面试和追问等语义是否齐全，不要求固定章节名；`--no-code` 允许在证据或验证章节保留源码定位，但会拦截正文中的源码导览。

## 安装

将仓库放到 Codex Skills 目录：

```bash
git clone https://github.com/zhouzhihui624/agent-resume-highlight-extractor.git \
  ~/.codex/skills/agent-resume-highlight-extractor
```

重新打开 Codex 会话后，通过 Skill 名称显式调用，或者直接提出与项目亮点、简历包装和面试准备相关的请求。

## 使用示例

```text
使用 $agent-resume-highlight-extractor 扫描当前项目，提取 4 个适合
AI 应用开发实习生简历的亮点。每个亮点需要包含简历一句话、通俗流程、
底层操作原理、STAR 面试话术、高频追问和项目证据。可以直接包装成
实习生工作，并补充机制对应的结果价值和指标方向。
```

也可以要求它只输出严格格式的简历内容：

```text
从当前项目中只写 2 条中文简历 Bullet，每条不超过 65 个汉字。
只要 Bullet；没有精确指标时，用机制能够推出的定性结果。
```

## 核心原则

1. **先还原机制，再包装**：亮点的流程、决策和失败边界必须能够回到项目证据。
2. **实习包装优先**：项目能力可以直接收敛成有限实习职责，不要求先核对个人提交归属。
3. **结果要有力度也要能守住**：主动写机制可推出的价值、上线用途和指标方向；精确数字与实际生产上线事件需要材料或用户提供。
4. **宁缺毋滥**：不为满足数量要求而保留重复或薄弱亮点。
5. **讲得清才算掌握**：先解释问题和完整流程，再介绍术语、底层机制与面试表达。
6. **缩小范围，不降低深度**：实习生亮点应收敛到可信模块，同时保留状态、失败和工程取舍。
7. **事实边界不能升级**：同进程不等于分布式，建议不等于门禁，候选制品不等于已验证结果。
8. **一条主线，多级展开**：短版和长版共享同一问题、个人任务、设计锚点、结果和边界。
9. **清晰不等于删细节**：单文档重构先迁移已核验事实，核心规则和状态跟着流程讲，完整矩阵与低频异常再进入附录。
10. **实现跟着流程讲**：整体图与三个步骤一一对应，关键对象、判断、状态、失败和验证在对应步骤首次讲清。
11. **校验语义而非标题**：检查问题、流程、实现、失败、验证和面试材料是否完整，不强制所有文档使用同一组章节名。

## 适用边界

这个 Skill 负责分析已有项目并组织有主体性、可深入追问的实习简历与面试材料。默认可以从项目能力推导有限职责和定性价值，但不会发明项目中不存在的机制，也不会把没有材料的精确数字或生产上线事件写成事实。用户明确要求 ownership 审计时，可切换为证据严格模式。
